01 / THE IDEA

Skills work alone.
Can they work
together?

A successful skill can leave the robot in a state that the next skill cannot use. Recursia improves the shared mechanisms that make composition possible.

Abstract

Skills that succeed in isolation can fail when composed into a long-horizon robot task. Their tools may lack a required capability or report completion before execution has finished, and one skill may leave a state from which the next cannot reliably start.

We introduce Recursia, a stack-aware, validation-gated recursive self-improvement framework for coding agents in zero-shot long-horizon robot manipulation. The agent improves a shared executable stack across tools, reusable skills with execution contracts, skill handoffs, and verification. Guided by source-side failure attribution, it generates missing tools or repairs shared components.

Candidates must pass generality checks, mechanism-level tests, and paired regression tests before acceptance. The resulting stack is frozen and reused unchanged on target tasks through declarative adapters: a repair learned from one source failure becomes executable functionality available to multiple skills and unseen compositions.

02 / THE METHOD

A repair that travels
with every composition.

Experience is retained as shared executable functionality. Each accepted change becomes part of a versioned stack.

01

Execute & attribute

Run a source task and identify the first supported execution failure.

02

Propose a shared repair

Add a missing tool or update a tool, skill contract, handoff, or verifier.

03

Validate & retain

Check generality, test the mechanism, and compare paired outcomes and regressions.

04

Freeze & compose

Reuse accepted code on unseen target compositions without persistent repair.

↔

Completion is not readiness. A predecessor's achieved goal does not guarantee its successor's prerequisites. Recursia makes that boundary explicit.
